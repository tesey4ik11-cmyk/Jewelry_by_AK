# Jewelry by AK — сборка сайта для публикации

В этой папке **только то, что нужно сайту**. Её содержимое можно целиком
загружать на хостинг или в GitHub — ничего лишнего и ничего не сломается.

```
index.html          главная страница (и единственная)
css/styles.css      стили
js/shop.config.js   ← украшения, цены, контакты
js/app.js           логика сайта
admin/              ← ПАНЕЛЬ УПРАВЛЕНИЯ (открывается на сайте: /admin/)
assets/img/         фотографии украшений (WebP + JPEG, 3 размера)
assets/logo-ak.svg  логотип и иконка сайта
robots.txt          панель не индексируется поисковиками
deploy.json         репозиторий для панели (нужен только для Vercel и своего домена)
.nojekyll           нужно для GitHub Pages
```

Всего 57 файлов, 4,6 МБ.

Ничего не собирается и не компилируется — это обычные HTML, CSS и JavaScript.
Папку можно просто открыть двойным кликом по `index.html` (сайт работает
без интернета; только шрифты подгружаются из сети, а без них включится
системный шрифт).

---

## Как менять украшения, цены и контакты

Через **панель управления на самом сайте**: откройте `https://ваш-адрес/admin/`.

При первом входе панель попросит **токен GitHub** — он создаётся один раз
на странице `github.com/settings/tokens` (галочка `repo`). После этого правки
сохраняются **коммитом в репозиторий**, а GitHub Pages или Vercel сам
пересобирает сайт за 30–60 секунд. Никакие файлы вручную загружать не нужно.

Токен хранится только в браузере владельца и отправляется только на `github.com`.

### Если сайт на Vercel или на своём домене

Панель не сможет угадать репозиторий по адресу. Впишите его в файл
**`deploy.json`** в корне сайта:

```json
{
  "owner": "ваш-логин-на-github",
  "repo": "название-репозитория",
  "branch": "main"
}
```

Для GitHub Pages этого делать не нужно — панель определит репозиторий сама.

## Как выложить на GitHub Pages

### Вариант А. Репозиторий только под сайт (самый простой)

1. Создайте на GitHub новый публичный репозиторий, например `jewelry-by-ak`.
2. Загрузите в него **содержимое этой папки** (не саму папку) — так, чтобы
   `index.html` оказался в корне репозитория.
   Через сайт GitHub: `Add file → Upload files`, перетащите файлы и папки.
3. В репозитории откройте `Settings → Pages`.
4. В разделе **Source** выберите `Deploy from a branch`,
   ветку `main` и папку `/ (root)`. Нажмите **Save**.
5. Через 1–2 минуты сайт откроется по адресу:
   `https://ваш_логин.github.io/jewelry-by-ak/`

### Вариант Б. Если сайт лежит в подпапке репозитория

Можно положить папку `publish` в репозиторий как есть и указать её в настройках:

`Settings → Pages → Source: Deploy from a branch → main → /publish`

### Вариант В. Через Git в командной строке

```bash
cd publish
git init
git add .
git commit -m "Сайт Jewelry by AK"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/jewelry-by-ak.git
git push -u origin main
```

Дальше так же включите Pages в `Settings → Pages`.

## Два шага после публикации

1. **Проверьте контакты.** В `js/shop.config.js` сейчас демонстрационные
   Telegram, WhatsApp и телефон (ВКонтакте указан настоящий). Замените их
   на свои и загрузите файл заново — иначе кнопки будут вести в никуда.

2. **Подставьте адрес сайта в превью для мессенджеров.** В `index.html` найдите
   строку `<meta property="og:image" content="assets/img/portrait-lg.jpg">`
   и укажите полный адрес, например:
   `<meta property="og:image" content="https://ваш_логин.github.io/jewelry-by-ak/assets/img/portrait-lg.jpg">`
   Тогда при отправке ссылки в Telegram или WhatsApp появится фотография.

---

## Обновление сайта

После правок в `js/shop.config.js` (цены, новые украшения, контакты) достаточно
загрузить этот файл в репозиторий заново — GitHub Pages обновит сайт
в течение минуты. Пересобирать ничего не нужно.

Если менялись `index.html`, стили или добавлены новые фотографии — в папке
проекта выполните `node tools/build-publish.js`, он заново соберёт эту папку,
затем загрузите изменения в репозиторий.

---

## Если нужен свой домен

`Settings → Pages → Custom domain` — впишите домен (например `jewelrybyak.ru`)
и следуйте подсказке GitHub по настройке DNS. GitHub добавит в репозиторий
файл `CNAME` автоматически.
